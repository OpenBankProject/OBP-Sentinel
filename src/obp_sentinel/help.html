Buttons on a finding

How much it matters to you

  • Relevant, Important and Urgent say how much a finding matters to you. The finding stays where it is. Sentinel learns from them and shows first the kinds of finding you rate: Important counts twice and Urgent three times. Urgent also puts the finding at the head of the Fix this queue.
  • Skip for now snoozes the finding. It comes back later.
  • Dismiss hides the finding and its log messages for good. Say why in the comment box first: the analyst reads it and will not raise that kind of finding again.
  • The Your ratings tabs list the findings you gave each rating that are not done yet. On the Urgent, Important and Relevant tabs, Fix all queues Fix this, with tests, for each of them. Fix all without tests does the same without running tests; CI runs them once you push.

History

  • Trace history lists the commits that changed the lines the finding names, back into the Lift code. Claude then says which commit introduced the problem.

Acting on a finding

What each button leads to is shown underneath it.

  • Save comment keeps your comment with the finding, and Senti answers it within a few minutes, under the finding. Ask it anything about the finding or its fix. If you ask it to do something it can do (rate the finding, skip it, dismiss it, mark it fixed, rescan it, or fix it again), it does that one thing and says so. Fix it again takes a staged fix back out of your working tree first, unless you have changed those files since. Only your latest comment and its answer are shown; Fix this follows every comment on the finding, and the analyst reads them.
  • Fix this saves the comment box, then queues the finding. Claude fixes it in Sentinel's own worktree of OBP-API, following your comments, and runs the tests that cover it. If they pass, Sentinel stages the change in your working tree. Fixes are made one at a time: the next starts once you have committed or discarded the one before.
  • Fix this without tests is the same, but faster. Claude adds the test scenarios and compiles, but runs no tests; they run in the cloud (CI) once you push. The fix is marked "tests not run" until then.
  • Should be fixed now says you think it is fixed. The finding moves to Done, and the analyst checks that its log errors dropped, and says so if not.
  • Rescan has Claude read the code the instance runs now and answer in one line. If Claude finds it fixed, naming the commit that fixed it, the finding moves to Done. Any other answer changes nothing. It reads the deployed commit, so a fix you have committed but not deployed still shows as an issue.
  • If Fix this finds that a commit has already fixed the problem, it changes nothing and moves the finding to Done, naming that commit.

A fix in your working tree

Under Fix this, Now says where the fix is today, read from git each time you open the finding: staged and not committed, committed and not pushed, pushed but not yet running on the instance, or running there. What Senti did is Claude's report from the time of the fix, and does not change. Staged means waiting for the next commit: git add (or Stage) puts changes there, and git commit saves them.

Review the change in your IDE and change it if you like. Sentinel commits only when you press Commit.

  • Stage adds the fix's files again, with any changes you made to them.
  • Unstage takes them out of what is staged. Your changes stay in the files. Unstaging in your IDE does the same.
  • Commit commits what is staged, with the one-line message shown. It refuses if files other than the fix's are staged. The finding then moves to Done, and the next queued fix starts.
  • Copy the commands copies the same git commands, to run in a terminal instead.
  • Discard takes the fix back out of your working tree. The next queued fix then starts.

Findings from SonarCloud

A finding whose evidence starts "SonarCloud reports" comes from SonarCloud's analysis of OBP-API, read every hour. Sentinel keeps only security issues, security hotspots, serious reliability issues and new issues on your pull request. Each links to the issue on SonarCloud. Static analysis can be wrong, so read the code before you press Fix this. When SonarCloud stops reporting it, the finding moves to Done.
